# Verification flags — 03 — Semiconductor Memory (CH3 slides 1–33)

Six defects found. Four substantive, two cosmetic.

**What was checked.** Every equation on slides 1–33 for dimensional and algebraic consistency,
symbol slips, mislabelled results and self-reference; every numerical claim recomputed in Python
(the address-size arithmetic on slide 12, the capacity arithmetic on slide 25, the whole Hamming
worked example and its 13-row syndrome table on slides 27–29, the SEC-DED parity bit and the
check-bit range table on slide 30, and the ROM sizing on slide 32); every gate-level schematic
re-simulated over its full input space (the SRAM latch cell on slide 15, the binary cell on
slide 23); every transistor-level schematic traced net by net from the render (the six-transistor
cell on slide 17, the DRAM cell on slide 19). Both image-only slides (20, 21) were read from the
PNG renders, not from the text layer.

### V03-1 · CH3 slide 15

**Prints:** an SRAM latch memory cell built from one NAND gate (inputs Select and Data in), one
inverter driven by that NAND's output, and a cross-coupled NAND pair drawn in De Morgan form
(OR shape with bubbled inputs); the upper NAND's output is labelled Data out.

**Should be:** the inverter belongs on the **Data in** path, feeding a **second** gating NAND:
$\overline{S} = \overline{\text{Select}\cdot\text{Data in}}$ and
$\overline{R} = \overline{\text{Select}\cdot\overline{\text{Data in}}}$, with the cross-coupled NAND
pair unchanged.

**Why:** as drawn, $\text{Select} = 0$ forces $N = 1$ and $\overline{N} = 0$; the lower NAND is then
pinned at $\overline{Q} = 1$ and the upper NAND settles at $Q = 0$ regardless of what was stored. The
cell holds a $0$ but loses a $1$ the moment it is de-selected, so it is not a memory cell. Repeat the
check by enumerating the four $(\text{Select}, \text{Data in})$ combinations from both latch start
states — all four rows with $\text{Select} = 0$ settle to $Q = 0$. With the corrected wiring, both
$\overline{S}$ and $\overline{R}$ go to $1$ when de-selected and the latch holds.

**Class:** substantive — the figure is reused on slide 16 as the array's cell, so the same defect
propagates.

### V03-2 · CH3 slide 17

**Prints:** a box headed "**B = 1**", followed by "Address Line is activated (T5 = ON, T6 = ON)" and
"T2 = OFF, T3 = OFF, T1 = ON, T4 = ON", over a six-transistor cell in which $T_3$ and $T_4$ are PMOS
pull-ups, $T_1$ and $T_2$ NMOS pull-downs, $C_1$ and $C_2$ the storage nodes, and $T_5$, $T_6$ the
access transistors to bit lines $B$ and $\overline{B}$.

**Should be:** $B = 0$ (equivalently $\overline{B} = 1$).

**Why:** the four listed transistor states are self-consistent, but only for $C_1 = 0$, $C_2 = 1$.
Tracing the cross-coupling on the render, $C_2$ drives the gates of $T_3$ and $T_1$ and $C_1$ drives
the gates of $T_4$ and $T_2$. $T_1$ ON therefore needs $C_2 = 1$; $T_3$ OFF follows for the PMOS on
the same gate; $T_2$ OFF needs $C_1 = 0$; $T_4$ ON follows. Bit line $B$ reaches $C_1$ through
$T_5$, so $B = C_1 = 0$. If the heading is taken as authoritative instead, all four transistor
states must be inverted.

**Class:** substantive — the heading and the body of the same box cannot both be right, and an exam
answer built on either one is wrong half the time.

### V03-3 · CH3 slide 18

**Prints:** "**Write** — WL = 0; Data is held in Latch mode" and "**Read** — WL = 1; Access
Transistors are turned ON".

**Should be:** "**Hold (standby)** — WL = 0; data is held in latch mode" and "**Read or write** —
WL = 1; access transistors are turned on".

**Why:** WL = 0 turns both access transistors off, isolating the cross-coupled inverters from the
bit lines. Nothing can be written into a cell that is disconnected — and the slide's own second line
says so, describing the state as "held in Latch mode", which is the definition of hold, not write. A
write needs WL = 1 so the bit-line write drivers can overpower the feedback loop.

**Class:** substantive — as printed, the write procedure cannot work.

### V03-4 · CH3 slide 29

**Prints:** in the syndrome table, the row for an error at position 12 reads
$C_8 = 1$, $C_4 = 0$, $C_2 = 0$, $C_1 = 0$.

**Should be:** $C_8 = 1$, $C_4 = 1$, $C_2 = 0$, $C_1 = 0$.

**Why:** position 12 is covered by both $C_8 = \text{XOR}(8,9,10,11,12)$ and
$C_4 = \text{XOR}(4,5,6,7,12)$, so flipping bit 12 flips both check bits. The one-line check is the
principle the whole scheme rests on — the syndrome read as a binary number is the error position, and
$1100_2 = 12$ whereas the printed $1000_2 = 8$. As printed, the table gives the same syndrome for an
error at position 8 and at position 12, so the correction logic would "correct" the wrong bit and
silently introduce a second error. The other twelve rows were recomputed by flipping one bit of
$001110010100$ at a time and all are correct.

**Class:** substantive — wrong number, and it breaks the decoder's one-to-one property.

### C03-1 · CH3 slide 8

**Prints:** two panels of the same $8 \times 8$ byte-organised array. The write panel shows address 3
holding $11111100$; the read panel shows address 3 holding $11000001$.

**Should be:** one value, consistently. Rows 0, 1, 2, 4, 5, 6 and 7 are identical in both panels, and
row 5 of the read panel is exactly the byte written in the write panel ($10001101$), so the two
panels are unambiguously the same array before and after the write.

**Why:** the write operation touches address 5 only, so address 3 cannot change between the panels.

**Class:** cosmetic — the write and read *procedures* the slide teaches are unaffected; only the
illustrative contents disagree.

### C03-2 · CH3 slide 33

**Prints:** the text lists **four** ways of programming a ROM (mask, PROM/fuse, EPROM/ultraviolet,
EEPROM/electrical), while the tree beneath draws **five** family members as siblings of ROM: Mask
ROM, Programmable ROM (PROM), Erasable PROM (EPROM), Ultraviolet EPROM (UV EPROM), Electrically
Erasable PROM (EEPROM).

**Should be:** either four boxes, or a two-level tree in which UV EPROM and EEPROM hang below EPROM.

**Why:** item 3 of the text defines EPROM *as* the ultraviolet-erasable part, so "EPROM" and "UV
EPROM" are the same device listed twice; and EEPROM is by construction an erasable PROM, i.e. a
sub-type of EPROM rather than a sibling.

**Class:** cosmetic — a taxonomy/counting mismatch, no numerical or logical claim depends on it. It
matters only because "name the members of the ROM family" has two defensible answers depending on
which half of the slide is used.
