## Substantive

### V10-1 · CH6 slide 13

**Prints:** the loop-exit decision of the multiplier flowchart as **"Is Count $n$ ?"**
**Should be:** **"Is Count $= 0$ ?"**
**Why:** the initialisation box on the same flowchart sets $\text{Count} \leftarrow n$, and the loop
body on the same flowchart does $\text{Count} \leftarrow \text{Count} - 1$, so the counter counts
*down*. The table printed on the left of the same slide confirms it: the Count column runs
$100\,(4) \to 011\,(3) \to 010\,(2) \to 001\,(1) \to 000\,(0)$ and the algorithm terminates at 000.
Taken as printed, the test is true on the very first pass — before any decrement has had an effect —
so the loop would exit immediately and no partial product would ever be accumulated.
**Class:** substantive — it inverts the termination condition of the algorithm the whole slide is
teaching, and the reader has the correct behaviour sitting next to it in the table.

### V10-2 · CH6 slide 21

**Prints:** the last two of the eight rows that replace PLA row 5 as
`001 0 1 0 0 1 0` and `001 0 1 0 0 1 1`
(columns $ABC$, $Rb$, $Reset$, $D_7$, $D_{711}$, $D_{2312}$, $Eq$)
**Should be:** `001 0 1 1 0 1 0` and `001 0 1 1 0 1 1` — that is, $D_7 = 1$ in both.
**Why:** row 5 of the slide-20 table has three dashes, in the $Reset$, $D_7$ and $Eq$ columns, so its
expansion is the eight combinations of $(Reset, D_7, Eq)$ in the order 000, 001, 010, 011, 100, 101,
**110**, **111**. The slide's first six rows follow that order correctly; rows 7 and 8 repeat rows 5
and 6 byte for byte, i.e. they print 100 and 101 a second time instead of 110 and 111. The
combinations $Reset = 1$, $D_7 = 1$ are therefore left unprogrammed and the controller would have no
defined next state for them.
**Class:** substantive — two of the eight product terms are missing from the programmed device, and
the slide's whole purpose is to show how a don't-care row is expanded.

### V10-3 · CH6 slide 34

**Prints:** a two-input AND gate fed by $A_3$ and $A_4$, whose output is taken into an **OR** gate
whose other input is $T_1$; the OR gate drives the D input of the $G_1$ flip-flop. As drawn,
$D_{G1} = A_3A_4 + T_1$.
**Should be:** a three-input **AND** on $T_1$, $A_3$ and $A_4$ — $D_{G1} = T_1A_3A_4$.
**Why:** slide 33, one slide earlier, prints $D_{G1} = T_1\,A_3\,A_4$ and derives it from the state
table; the state table has exactly one row with $G_1^{+} = 1$, namely $G_1G_0 = 01$ with
$A_3A_4 = 11$. The drawn and required functions were compared over all 24 combinations of control
state and $(S, A_3, A_4)$ and differ in **10** of them. The failure is immediate: with the printed
circuit, $D_{G1} = 1$ throughout $T_1$, so the machine leaves $T_1$ for $T_2$ after a single clock
period regardless of the counter, $F$ is set, and the counter stops at $0001$ instead of $1101$. The
OR gate one row above, which correctly forms $D_{G0} = T_0S + T_1$, is what makes the error easy to
miss — the two gates are drawn with the same symbol.
**Class:** substantive — the circuit does not implement the equation printed on the previous slide,
and the resulting machine does not solve the stated problem.

## Cosmetic

### C10-1 · CH6 slide 18

**Prints:** step 2 as "For each of these link paths that lead into the state." and step 3 as "For
each of these link paths, find a term that is1 when the link path is followed. That is, for a link
path from to, the term will be 1 if the machine is in state and the conditions for existing to are
satisfied".
**Should be:** step 2 — "For each of these **states**, find all of the link paths that lead into the
state." Step 3 — "…for a link path from **$S_i$** to **$S_j$**, the term will be 1 if the machine is
in state **$S_i$** and the conditions for **exiting** $S_i$ to $S_j$ are satisfied." Also "is1"
needs a space.
**Why:** the state symbols have been dropped by the slide software, leaving three dangling
prepositions, and "existing" is a typo for "exiting". The equations printed on the same slide,
$B^{+} = A'B'X + A'BX + ABX$ and $A^{+} = A'BX + ABX$, are both **correct** — verified against the
next-state table of the slide-10 chart.
**Class:** cosmetic — the procedure is unreadable as printed but the mathematics is untouched.

### C10-2 · CH6 slide 30

**Prints:** the counter bits as $A_3\,A_2\,A_1\,A_0$, with $A_2$ and $A_3$ fed back to the
controller.
**Should be (for consistency with the rest of the example):** $A_4\,A_3\,A_2\,A_1$, with $A_3$ and
$A_4$ fed back — the numbering used by the problem statement on slide 24 and by slides 25–29 and
31–34.
**Why:** slide 30 is a redraw of the same design from a different edition of the source textbook,
which indexes the counter from 0. The two figures describe the same two flip-flops — the MSB and the
bit below it — but a reader moving between slides 29 and 30 will read $A_3$ as two different bits.
**Class:** cosmetic — no equation changes, but the clash is worth knowing before an exam question
quotes one figure and the marking scheme the other.

### C10-3 · CH6 slide 40

**Prints:** the $K$ decision box inside state $A$'s SM block, and the two $J$ decision boxes inside
state $B$'s SM block, each with a **single exit path and no 0/1 branch labels**.
**Should be:** either delete those boxes, or draw both branches, label them 0 and 1, and let them
merge into the same exit.
**Why:** slide 9's own rule 1 requires exactly one exit path for every valid combination of input
variables, and Fig. 10-1 defines a decision box as having a true branch and a false branch. In state
$A$ the next state depends on $J$ alone and in state $B$ on $K$ alone, so those three boxes cannot
change the outcome — which is why the original draughtsman merged their exits. The **behaviour** of
the chart is correct: both state tables on slides 39 and 40 were checked against $Q^{+} = D$ and
$Q^{+} = JQ' + K'Q$ and agree in all eight state-and-input combinations.
**Class:** cosmetic — notation only, but a student copying the drawing into an exam answer would
lose the mark for a malformed decision box.

### C10-4 · CH6 slide 36

**Prints:** "The weight of a binary number is defined by as the number of 1's present in it binary
representation".
**Should be:** "The weight of a binary number is defined as the number of 1s present in its binary
representation."
**Why:** two typos — a stray "by" and "it" for "its" — in the single sentence that defines the
quantity the whole worked example computes.
**Class:** cosmetic.
